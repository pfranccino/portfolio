## HIGH (Hard Gate)

1. **R-32** With the mobile drawer open, the page behind it is still in the tab order. Verified: at 375px, open "Menú", focus lands on "Sobre", one Shift+Tab moves focus to the Contacto "Spotify" link, which sits behind the full-screen drawer (1925px down, body scroll locked). A keyboard or switch user loses the focus indicator, and VoiceOver/TalkBack swipe into hidden content the same way. Closed drawer is fine (`inert`, Escape returns focus to "Menú"). `Header.jsx:60-75`. Fix: set `inert` on `main` and `footer` while `menuOpen`, so focus can only move between the header (brand, "Cerrar") and the drawer.

2. **R-39** Eight links have an accessible name that does not contain their visible text (WCAG 2.5.3 Label in Name, level A). A voice-control user who says what they see ("clic en Seguirme en Medium") does not reach the link.
   - "Ver en GitHub" ×4 is named "Ver toml-deps-checker en GitHub (…)", which splits the visible words. `Trabajo.jsx:50`
   - "github.com/pfranccino/<repo>" ×2 is named "Repositorio <repo> en GitHub (…)". `Skills.jsx:26`
   - "Seguirme en Medium" is named "Mi perfil en Medium (…)". `Articulos.jsx:99`
   - "Escuchar en Spotify" is named "Escuchar la playlist Mood de Paul Franccino en Spotify (…)". `Sobre.jsx:61`

   Fix: start each name with the visible text and keep the CLAUDE.md suffix, e.g. "Ver en GitHub: toml-deps-checker (se abre en otra pestaña)", "Seguirme en Medium (se abre en otra pestaña)". The article cards and the Contacto channels already pass (their names contain the title or the channel label).

3. **R-39** Interaction states are incomplete.
   - No `:active` state on any text link, the theme button or the burger. Only `.btn` and `.mail` have one (`index.css:181`, `Contacto.module.css:53`).
   - Hover is color-only on the header nav (ink-2 to ink, 1.84:1 between the two), `.secondary`, `.hobbyLink`, `.repo` and the Medium link (underline yellow to ink). In dark mode that underline goes from yellow to light grey, two light colors that are hard to tell apart.
   - `.burger` and `.brand` have no hover state.
   - `cursor: pointer` works on every link and button (checked in the browser) but is set per component (`.btn`, `.theme`, `.burger`), not once in the base layer as R-39 asks. A future button would ship with the arrow.

   Fix: one base rule for `a[href], button { cursor: pointer; }`, the existing 1px press for `:active` on links and buttons, and a non-color hover cue (the arrow nudge the external links already use, or the underline thickening).

4. **R-26 / R-34** The theme button label can go stale. `useState(currentTheme)` reads the OS theme once and nothing listens for changes. If the OS switches theme while the page is open (automatic dark mode at sunset) and no theme is saved, the page follows the OS but the button keeps the old label, and its first click sets the theme the page already shows, so nothing visible happens. `Header.jsx:16-26`. Found by code inspection, not reproduced (the browser tool cannot switch the OS theme). Fix: while `data-theme` is unset, subscribe to the `prefers-color-scheme` media query and update `theme`.

5. **R-38 / C-5 [confirmar]** "Suelo contestar dentro de 48 hrs." (`Contacto.jsx:19`) is a specific promise. It arrived with Redesign v2 (`40db375`), not from a stated habit. Keep it only if it is true; otherwise cut the sentence.

## MEDIUM (Purpose-Gate and supplementary checks)

6. **Non-text contrast (antislop-human) [R-37]** In light mode the active nav item is marked by a 2px yellow line at 1.45:1 on `--bg` plus ink instead of ink-2 (1.84:1 apart). Both are under the 3:1 that WCAG 1.4.11 asks for a state indicator, and the item has no `aria-current`, so screen readers don't get the state either. Seen in the browser: "Trabajo" active reads almost the same as its neighbours. `Header.jsx:136`, `Header.module.css:103-106`. CLAUDE.md makes yellow a fill-only color in light mode, so this is your call. Option: add `aria-current="location"` and a second cue that doesn't depend on yellow (weight 650, or an ink underline in light mode only). Link underlines elsewhere are fine as they are, because bold ink text already identifies those links, and the current job's yellow rule is backed by the text "a hoy".
